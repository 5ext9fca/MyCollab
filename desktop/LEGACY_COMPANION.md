# MyCollab 旧版 macOS 本地伴侣

本文仅适用于旧版 `MyCollab Companion.app`，不适用于新的完整桌面客户端。新客户端说明见 [桌面客户端指南](README.md)。

本地伴侣帮助你管理电脑上的 Agent。任务协作继续在浏览器中完成；应用负责保存连接、检查环境、启动和停止 Runner，并在断线后恢复结果回传。

当前提供 macOS 版本。应用已包含 Runner 所需的 Python 环境，你仍需安装 OpenCode 2.1.3，并用 `opencode auth login` 登录自己的模型供应商。

## 开始使用

1. 从维护者取得适合本机架构的 `MyCollab Companion.app`，放入应用程序目录后打开。
2. 在网站“本地 Agent”创建设备，复制本次显示的设备凭据。
3. 在伴侣填写网站根地址、设备凭据、模型名称与 OpenCode 的完整路径。例如 Apple Silicon Homebrew 安装通常在 `/opt/homebrew/bin/opencode`。
4. 网站使用内部 HTTPS 证书时，向管理员取得可信 PEM 根证书，填写“内部 CA 证书”；公共 HTTPS 网站留空。
5. 点击“保存配置”和“连接自检”，确认 CLI 与服务器可用，再点击“启动”。自检不会调用模型，也不会验证供应商额度。
6. 在浏览器中使用文本辅助或导出 Agent 需求文档；模型调用可能产生费用，生成后仍需人工采纳。

模型名称可用 `opencode models --standalone` 查看。凭据保存后不会重新显示；留空保存会保留原凭据，切换网站必须填写该网站的设备凭据。运行期间修改配置前先停止 Runner。

## 运行与恢复

关闭窗口会保留菜单栏图标；点击图标可重新打开窗口，选择“停止并退出”会结束 Runner 和正在执行的模型进程。“登录电脑时启动”默认关闭，只有主动开启后才在登录时自动启动伴侣和 Runner。

“待回传”表示模型已经返回结果，应用会在恢复网络或再次启动后重传同一份结果；不会因此重新调用模型。“已拒收”表示服务器已结束请求、内容变化或结果不被接受，原结果仅在本机保留最多 24 小时，不会自动覆盖网站内容。模型执行中途退出后不会自动重跑，需要在网站明确发起新请求。

不要让命令行 Runner 与伴侣同时使用同一个设备；重复启动会被本机锁阻止。供应商凭据继续由 OpenCode 管理，MyCollab 设备凭据和待发结果只保存在本机私有目录。

## 更新与排错

- “CLI 不可用”：检查 OpenCode 完整路径；“版本不兼容”：使用已验证的 2.1.3。
- “服务器不可用”：检查网站根地址、网络和内部 CA；应用不允许跳过 TLS 验证。
- “凭据无效”：在网站重新创建设备并更新配置，旧设备的结果不会自动发给新设备。
- Runner 意外退出：先自检，再手动启动；不会自动重试生成。
- 安装更新前先停止 Runner。配置了维护者签名更新源的构建可检查并安装更新；本地构建没有更新源时会明确提示手动安装。更新后从菜单栏退出并重新打开。

首次本地构建仅用于本机验证，不等同于已通过 Apple Developer ID 签名、公证的对外发行版。不要为了运行未知来源的版本关闭系统安全设置。
