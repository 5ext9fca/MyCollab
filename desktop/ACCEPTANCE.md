# 开发客户端双机验收

这份步骤用于 Windows x64 与 macOS 的开发包验收，不是正式发行。先使用维护者指定的同一源码版本安装包，并记录完整文件名；不要混用旧开发包。安装包、对应源码提交与校验值由维护者提供，只有构建成功不代表以下场景通过。

## 开始前

- 两台电脑连接同一普通局域网，并能访问同一个团队 HTTPS 网站。不要把一台电脑上的 `localhost` 地址填到另一台电脑。
- 分别使用自己的已批准账号登录。只使用验收文件与测试任务，不发送私人文件。
- 两端在“桌面设置”开启局域网访问，并处理系统询问。macOS 密码或钥匙串访问由本人在系统窗口确认；Windows 防火墙若询问，请核对应用和当前网络。记录拒绝/允许的实际选择，不关闭全局安全保护。
- 首轮保留系统默认网络配置，不启用原始 IP 测试开关。若正在使用 VPN 或虚拟网卡，记录当前状态，后续单独比较。
- 在两端创建专用接收文件夹，避免覆盖已有文件。每次传输都重新生成配对码。

## 先完成一个最小闭环

1. 两端打开“文件互传”。macOS 选择一份小文件，点击“生成配对码”。
2. Windows 输入配对码，点击“查看待接收文件”，核对文件名、大小和发送人，再点击“确认接收”。
3. 双方应显示传输成功，接收端显示“保存已校验文件”。点击保存，实际选择接收目录，并确认磁盘文件存在；只看到进度 100% 不算成功。
4. 核对页面显示的双方 SHA-256 一致，再计算下载文件的 SHA-256，与页面比较。
5. 交换发送与接收方向，重复一次。

计算文件摘要可使用系统已有命令（替换为实际文件路径）：

Windows PowerShell：`Get-FileHash -Algorithm SHA256 -LiteralPath 'C:\验收\文件.bin'`

macOS 终端：`shasum -a 256 '/实际路径/文件.bin'`

若一直显示“正在建立局域网直连”，记录两端提示与等待时间；等待约 70 秒观察是否明确失败。不要把“配对成功”记为“传输成功”。失败后取消或重新进入页面，再使用新配对码重试。

## 按顺序扩展

- 两个方向分别传空文件、普通文件、恰好 100 MiB 文件和含中文/空格文件名的文件。保存后逐份核对摘要。
- 配对后不确认，主动取消；重新配对后在传输中取消。双方都不应显示成功或提供未校验文件下载，随后能重新发起传输。
- 传输中尝试退出：先选择停留，确认页面仍能操作；再次退出并确认离开。另一端应最终显示中断或超时，不应无限等待。
- 拒绝局域网权限后尝试传输，再从系统设置恢复该应用的权限并重试。记录是否需要重新打开应用。
- 在一端临时断网后恢复，检查失败提示与新配对重试；在传输中睡眠再唤醒，检查是否明确失败或正确完成校验，不能假成功。
- 开启实际使用的 VPN/多网卡配置后重复小文件流程，记录网络差异。受限网络允许明确失败，不能据此修改全局安全设置。
- 在两端各自的受支持浏览器中登录同一网站，分别验证浏览器发送到桌面、桌面发送到浏览器。记录浏览器名称与版本。

同系统双机（Windows↔Windows、macOS↔macOS）需要额外设备，未实际运行就保留“未验收”，不以一台电脑的两个窗口替代。

## 安装与日常使用

- 记录系统版本、处理器架构、安装目录及安装是否需要额外运行环境。开发客户端本身不应要求安装 Node、Python 或 Rust；本地模型 CLI 是可选的另外配置。
- 登录后完成一项测试任务的发布、认领、提交与验收；刷新或重新登录后核对结果。
- 上传测试素材，查看图片、下载到自选目录，再退出账号；换另一个账号确认素材列表隔离。
- 本地 Agent 绑定、自检与启停按[客户端指南](README.md)执行。关闭窗口后从托盘恢复，再明确退出；未发起模型请求时不应自动调用模型。
- 若测试开机启动，先记录原设置，启用后重新登录系统检查仅打开客户端、不自动运行模型；验收后恢复原设置。
- 卸载前先退出应用。记录卸载结果及用户配置是否保留，不手动删除仍需恢复的待发结果。

## 回报格式

每个场景填写：

- 安装包文件名、源码提交、两端系统/架构与浏览器版本（如涉及）。
- 方向与文件大小；开始到连接成功、传输结束的大致秒数。
- 网络类型、VPN 状态、应用局域网权限及系统弹窗选择。
- 两端最终提示；文件是否保存、磁盘摘要是否与页面一致。
- 结论：通过 / 失败 / 未执行。失败时写最短复现步骤。

不要发送密码、设备令牌、完整 SDP、局域网地址或文件正文。未执行的场景保留空缺，由维护者记录为未验收。
